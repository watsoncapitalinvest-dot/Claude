Written 17 Nov 2026 by the CIV render desk (a Claude session) for whoever picks this up next - another AI or a person.
John Watson owns the project: a G.I. Joe-themed total conversion of OpenXcom (OXCE). This desk made the civilian walk
sheets, the nine cartel men, the extra animations, and the offline render machine + app that runs on John's PC.
Read all of it once. Section 13 (pitfalls) will save you hours.

======================================================================================================================
1. WHAT THIS IS, IN ONE PARAGRAPH
======================================================================================================================
The game shows every soldier as a sprite sheet: one PNG of 896 small pictures (poses and walk frames in 8 facings).
Those pictures are rendered in Blender from a rigged 3D model (.blend on a Mixamo skeleton) played through Mixamo
animation clips (.fbx), then assembled into the sheet with an outline ("ink") pass and the game's palette.
The RENDER MACHINE does that on John's PC with no cloud: drop a .blend in a folder, a finished, checked sheet comes
out. The APP is a window over the machine (start/stop, add models, progress, preview, pick extra animations) with an
EDIT LOOK window that changes a model's skins, colours and gear without opening Blender.

4. THE SHEET FORMAT (walk16, what the game reads)
======================================================================================================================
  <name>_body.png        2048 x 8960, 8-bit palette (game palette), 128 x 160 cells, 16 cells per row = 896 frames
  <name>_body_rgb.png    same, full colour
  <name>_body_anchors.txt  896 lines, one per frame: hand and feet positions (the game hangs the gun on the hand)
  Layout: frame = base + facing * per + f.  facing 0 = up-right on screen, then clockwise.
    stand 0, kneel 64, aim 128, death 192, pstand 256, pkneel 320     (8 frames a facing)
    walk 384 (two-handed gun), pwalk 512 (pistol), swalk 640 (crouched), ewalk 768 (empty hands)   (16 a facing)
  Check every sheet: size 2048x8960, 896 anchor lines, 0 empty cells. Look at one walk row and the death row by eye.

5. HOW ONE MODEL BECOMES A SHEET (what the machine runs, in order)
======================================================================================================================
A) RENDER FRAMES  (build/sprites/render_char.py, needs bpy)
   python render_char.py --blend M.blend --clips "stand=a.fbx,kneel=b.fbx,...,walk=w.fbx,..." --frames 8
          --clipframes walk=16,pwalk=16,swalk=16,ewalk=16 --out FRAMES_DIR [--dirs 1,..,8] [--shade]
   A clip can also be an action inside a .blend:  name=C:\path\clips_17nov.blend#cast_spell_hold
   It writes FRAMES_DIR/<clip>/d<facing>_f<NN>_beauty.png and _id.png (part-ID pass for the outline) + meta.json.
   Clip names matter: names containing walk/run get their forward travel removed (walk in place);
   names starting with death keep the fall but not the slide, are not looped, and get a wider camera.
   Clips used for the SHEET:
     ARMED  stand = Rifle 8-Way\idle.fbx, kneel = Rifle 8-Way\idle crouching.fbx, aim = Rifle 8-Way\idle aiming.fbx,
            death = Rifle 8-Way\death from the front.fbx, pstand = Pistol\pistol idle.fbx,
            pkneel = Pistol\pistol kneeling idle.fbx
     CIVILIAN (unarmed): every still = Downloads\Standing Idle.fbx, except death (same as armed)
     WALKS (both): walk = Basic Shooter Pack\walking.fbx, pwalk = Pistol pack\pistol walk.fbx,
            swalk = Rifle 8-Way\walk crouching forward.fbx, ewalk = Action Adventure Pack\walking.fbx
B) ASSEMBLE  (build/sprites/assemble_sheet.py, plain Python: numpy scipy pillow)
   env W16=1 HAIR=<r,g,b or empty> FOLD_IDS=<ids or empty> XCOM_UNITS=<game UNITS folder> [PENIDS=.. PENPCT=.. etc]
   python assemble_sheet.py FRAMES_DIR OUT_DIR <name>      (OUT_DIR must exist)
   -> <name>_body.png, _body_rgb.png, _body_anchors.txt
C) CHECK  size / anchors / empty cells (render_cartel.check()), copy to Reference\sheets\<cartel|civ>\
D) EXTRAS  render_char again with the clips from clips_17nov.blend, 16 frames each, 8 facings; the machine pastes
   each clip into one PNG: extras\<name>_<clip>.png = 8 rows (facings) x 16 frames, raw (no outline, no palette).
Timings measured: sheet 13-14 min a model on the 2-core cloud box; extras ~1.4 min per clip. John's PC is faster.

THE INK (outline) SETTINGS - the "HAIR|FOLD|PEN" row
   The cloud pipeline keeps one row per character in render_cast.sh ink(). The machine reads, in this order:
   <name>.ink.txt beside the .blend (one line HAIR|FOLD|PEN, e.g. "48,38,32||TERMIDS=3,6,11 TERMMIN=90"),
   else the HAIR table in render_cartel.py (cartel nine + the 12 civilians), else outline only.
   PEN containing PENIDS= also adds --shade to render_char. Current standard (newest characters): the painted
   textures carry shading and fold lines, the renderer only adds the outline = no ink file needed.

7. THE APP AND EDIT LOOK (render_app.py + dress.py)
======================================================================================================================
  render_app.py (tkinter): imports render_cartel as M for paths and lists. Starts the machine as a child process
  (python.exe render_cartel.py --watch, no console window); Stop kills the whole process tree (taskkill /T /F).
  Progress = count of *_beauty.png in render_work\fr16_<name> / 896 (sheet) or extras_<name> / (clips*128).
  The current model = last "== name start" in render_log.txt with no done/FAILED after it.
  Preview panel: stand, walk, aim, death cells of facing 5 cut from the finished _body.png.
  Extras checkboxes rewrite extras.txt (the machine re-reads it before each model).

  EDIT LOOK window -> dress.py, run as  python dress.py --blend M.blend ...  (Blender's Python):
    --list                          prints DRESS_JSON {materials:[{name,image,tinted,tint}], gear:[...], props:[...]}
    --spec SPEC.json --out O.blend  applies: {"skins": {material: image_path}, "colours": {material: [r,g,b] | null},
                                    "gear": [...] (omit = unchanged, [] = none), "props_add": [...], "props_remove": [names]}
    --template MATERIAL --out x.png the material's image with that part's UV seams drawn in magenta (for the AI painter)
  Skins: replaces the Image Texture node's image (packed into the .blend). Colour: luminance-keeping recolour =
    RGBToBW(texture) x colour/meanLuminance into the Emission colour (null removes it). Materials are flat EMISSION
    (no lights in these renders) - anything new must be emission too.
  Built-in gear (bandana, cap, dome=helmet, vest+pouches, sunglasses, chain): simple meshes measured off the body
    (head and torso cross-sections by bone weights), rigidly weighted to one bone each, one shared material
    'cartel_gear' coloured by a 'gcol' colour attribute. The list is stored on the armature as arm['gear_spec'].
  Gear files (props): .glb/.gltf/.fbx/.obj imported, merged to one mesh, scaled to the attach point (head width,
    torso width, 0.25 m at the hip, 0.6 m in the hand), offset/rotated by the sliders, weighted 100% to one bone
    (Head, Spine2, Hips, RightHand, LeftHand). Its materials are converted to emission and given their OWN
    IDSWITCH with a constant part id (39) so they don't count against render_char's 6-material limit.
    Stored as objects named Prop_<file> with obj['gear_prop'] = the JSON it was added with.
  Face from photo: dress.py --faceview OUT.png builds the model's face seen from the front by splatting the skin
    texels of front-facing Head-weighted triangles (+ OUT.png.json: material, x0, z1, s = world metres per pixel).
    The user clicks left eye, right eye, mouth on the photo and on that view; spec "face": {photo, photo_pts (photo
    pixels), model_pts (world x,z), strength, cartoon 0-3, match 0-1}. apply_face(): affine from the 3 model points to
    the 3 photo points, every face texel samples the cartooned photo (median filter + quantize), weighted by an
    ellipse around eyes/mouth and by facing; the photo's average is shifted toward the skin's by 'match'. Written
    to a new packed image <tex>_face on the face material. Tested with an invented stand-in face on Ch42/Ch23/foot_b.
  Preview: dress to render_work\preview_<name>.blend, render stand + walk frame 0, facings 2,5,7.
  Apply: copies the old .blend to <folder>\_versions\<name>_<YYYYmmdd-HHMMSS>.blend, writes <name>.blend.new.blend,
    replaces. Undo: moves the newest version back. Both change the file time, so the machine re-renders.

11. TROUBLESHOOTING
======================================================================================================================
  Look in render_work\: render_log.txt (one line per step), <name>.render.log, <name>.assemble.log,
  <name>.extras.log, dress_<name>_*.log, machine_console.txt (the app's machine output), MACHINE_STATUS.txt.
  "No renderer"            -> py -3.13 -c "import bpy" fails: run SETUP_v3.bat or the pip line in section 3.
  "MISSING ...zip"         -> a pack zip is not in Downloads under that exact name.
  RENDER FAILED, log says "can't open file ...render_char.py" -> the kit's build\sprites folder is missing: restore.
  ASSEMBLE FAILED          -> usually XCOM_UNITS path wrong or OUT dir missing (the machine creates it).
  CHECK FAILED / empty frames -> look at the frames in render_work\fr16_<name>; often a clip that does not fit the
                              skeleton or a model with non-Mixamo bone names.
  Model renders in T-pose  -> the clip's bone names are not mixamorig: (fixed automatically for mixamorigN:).
  App window does not open -> run RENDER_MACHINE.bat (same machine, no window) and check tkinter: py -3.13 -m tkinter
  Material limit assert ("too many materials for the 40-step id") -> render_char allows 6 materials per model
                              (each takes 6 ids). Merge materials, or give extras their own IDSWITCH (see 7).

13. PITFALLS THAT COST TIME (read these)
======================================================================================================================
  1. NEVER re-export a clip to FBX from Blender for this pipeline. Blender's FBX export changes the bones' rest
     axes; render_char applies a clip's rotations onto the model's own skeleton, so the arms come out twisted.
     Keep edited clips as ACTIONS in a .blend and pass name=lib.blend#action (render_char supports it).
  2. Blender REUSES appended data from the same library path. If a model already has an action appended from
     clips_17nov.blend, loading again from that path silently gives you the OLD copy. Before re-embedding: delete
     the model's actions AND its bpy.data.libraries entries. For one-off test renders, copy the library to a new
     path first.
  3. The civilian/cartel .blend files are saved with the armature in REST position. Set
     arm.data.pose_position = 'POSE' before measuring a posed skeleton (render_char does this itself).
  4. Blender 5 actions are layered: fcurves live in action.layers[0].strips[0].channelbags[0].fcurves.
  5. The game camera looks down steeply: a hand BEHIND the body draws ABOVE the head on screen. Judge "arms up" by
     numbers (hand z vs HeadTop_End z), not only by the picture.
  6. Do not edit an evaluated mesh (obj.evaluated_get(...).to_mesh()) - Blender segfaults. Copy obj.data instead.
  7. assemble_sheet.py does not create its output folder.
  8. Containers/sessions restart and kill background jobs: push each finished sheet to git straight away.
  9. Gear and props must use EMISSION materials - there are no lights; a Principled material renders black.
 10. render_char counts every material: max 6 per model unless the material carries its own IDSWITCH node.
 11. Mixamo "with skin" downloads are ~120 MB, "without skin" ~2 MB; both work as clips. Numbered duplicates in
     Downloads ("Withdrawing Sword (3).fbx") are usually the same move on other characters - use the plain one.
