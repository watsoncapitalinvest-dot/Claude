HOW TO SEND BACK THE FACILITY NUMBERS
=====================================

The base has 104 rooms with art and no rules: nothing yet says what any of them
costs, how long it takes to build, or what it does. This describes the FORMAT the
numbers must arrive in so they can be loaded without being retyped.

The room list - every id, name and footprint - is FACILITY_MANIFEST.txt. Use its
file names to identify rooms. Do not invent rooms that are not on it.

Send ONE file, plain text, named facilities.yml. Nothing else in the message.


THE SHAPE
---------
One block per room, separated by a blank line, every key present, in this order.
If a value does not apply write 0 (or false). If something is unknown write
UNKNOWN rather than dropping the line.

- file: j_barracks.png
  id: STR_JOE_BARRACKS
  name: Barracks
  size: [1, 1]
  start: false
  lift: false
  buildCost: 120000
  buildTime: 10
  monthlyCost: 3000
  provides:
    personnel: 12
    storage: 0
    laboratories: 0
    workshops: 0
    crafts: 0
    radarRange: 0
    radarChance: 0
    defense: 0
    hitRatio: 0
    prisonSpace: 0
    psiLaboratories: 0
    training: false
  requires: []
  summary: >
    One sentence: what building this gets the player.


WHAT EACH KEY MEANS
-------------------
file          Exactly as in the manifest. This is how the room is matched to
              its art.
id            STR_ and capitals, unique. Derive it from the room name.
name          As the player sees it.
size          [width, height] in grid squares, copied from the manifest.
start         true only for rooms in the base the player begins with.
lift          true for the ONE room that is the entrance lift. Every other room
              must connect back to it.
buildCost     Dollars, whole number.
buildTime     Days, whole number.
monthlyCost   Dollars per month, whole number.

provides      What the room adds to the base. Most rooms provide ONE thing.
  personnel        soldiers, scientists and engineers housed
  storage          storage space
  laboratories     scientist places
  workshops        engineer places
  crafts           aircraft or vehicles it can hold
  radarRange       detection range in nautical miles
  radarChance      percent chance per check of spotting something in range
  defense          damage the base defences do to an attacking craft
  hitRatio         percent chance those defences hit
  prisonSpace      captured Cobra personnel it can hold
  psiLaboratories  places for brainwave research
  training         true if soldiers can train here

requires      Research that must be complete before it can be built, as a list
              of STR_ ids, e.g. [STR_COBRANIUM]. [] if none.
summary       One sentence, under 20 words, your own words.


HOW TO PRICE IT - THE ONE PRINCIPLE
-----------------------------------
The Pit has about 100 rooms where the original game had about 20, so each room
here does LESS than its original counterpart and costs less. A barracks is one
dormitory, not the whole living wing. Use the original game's figures as the
anchor and scale down:

  original                   cost      days  monthly   provides
  Living Quarters          400,000      16   10,000    50 personnel
  Laboratory               750,000      26   30,000    50 laboratories
  Workshop                 800,000      32   35,000    50 workshops
  General Stores           150,000      10    5,000    50 storage
  Hangar                   200,000      25   25,000     1 craft
  Small Radar              500,000      12   10,000    1500 range, 10 chance
  Large Radar              800,000      25   15,000    2250 range, 20 chance
  Missile Defences         200,000      16    5,000    500 defense, 50 hit
  Alien Containment        400,000      18   15,000    10 prison

  A specialist room (lab, workshop, radar) at roughly half the original cost
  and half the capacity; a basic room (bunks, stores) at roughly a quarter.
  A hangar holds one craft whatever the base, so it stays near the original.

Rooms with no original counterpart - a firing range, a motor pool, a briefing
room - say in the summary what they are for. If what they provide does not fit
any key above, set everything to 0 and say so in the summary, so the mechanic
can be designed rather than squeezed into the wrong number.


DO NOT INCLUDE
--------------
    - Markdown, headings, bullets or commentary. Plain YAML only.
    - Rooms not in the manifest.
    - Any logo or trademark in any text.


CHECK BEFORE SENDING
--------------------
    1. Is there one block for every room in the manifest, matched by file?
    2. Is exactly one room marked lift: true?
    3. Does every block have every key, in order, with whole numbers?
    4. Is the whole file valid YAML - two-space indents, no tabs?

More than about forty rooms: split across facilities_1.yml, facilities_2.yml,
each complete and valid on its own.
