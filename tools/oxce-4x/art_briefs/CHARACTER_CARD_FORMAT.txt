HOW TO SEND BACK THE CHARACTER CARDS
====================================

You are compiling the file cards for the characters in a G.I. Joe conversion of
a turn-based squad game. This describes the FORMAT the answer has to arrive in.
It is not about what to write - it is about how to hand it over so it can be
loaded without being retyped.

Send ONE file. Plain text, named characters.yml. Nothing else in the message.


THE SHAPE
---------
One block per character, separated by a blank line. Every block has exactly the
keys below, in this order, with no extra keys and none left out. If something is
genuinely unknown write UNKNOWN rather than dropping the line or guessing.

- id: STR_SNAKE_EYES
  name: Snake Eyes
  codename: Snake Eyes
  realname: UNKNOWN
  side: joe
  role: commando
  birthplace: UNKNOWN
  specialty: Infiltration and silent elimination
  secondary: Hand-to-hand instruction
  rank: sergeant
  joined: 1982
  stats:
    tu: 68
    stamina: 94
    health: 46
    bravery: 80
    reactions: 72
    firing: 68
    throwing: 64
    strength: 38
    melee: 92
    psi: 20
  armor: STR_JOE_FATIGUES
  weapons: [STR_UZI, STR_COMBAT_KNIFE]
  summary: >
    One sentence. What this character is for, in play.
  article: >
    Three to six sentences. Written for the player to read in the in-game
    file index. Your own words throughout.


WHAT EACH KEY MEANS
-------------------
id          Capitals, underscores, starts with STR_. Must be unique. This is
            what the game and every ruleset refer to, so it never changes once
            sent. Derive it from the codename: Storm Shadow -> STR_STORM_SHADOW.

name        How it appears on screen. Mixed case, as a person's name.

codename    The field name. Often the same as name; give both anyway.

realname    Only if it is a matter of public record outside the toy line's own
            packaging. Otherwise UNKNOWN - do not invent one.

side        Exactly one of: joe, cobra, neutral.

role        One short lower-case word or two: commando, heavy weapons, medic,
            pilot, demolitions, intelligence, infantry, officer, saboteur.

birthplace  City and state or country. UNKNOWN if not established.

specialty   The character's primary military specialty, one line.
secondary   Secondary specialty, one line, or UNKNOWN.

rank        One of: private, corporal, sergeant, lieutenant, captain, major,
            colonel, general, commander, operative. Lower case.

joined      Four-digit year the character first appeared, or UNKNOWN.

stats       All ten numbers, every one present. Whole numbers.
            tu 40-80, stamina 40-110, health 25-60, bravery 10-100 in tens,
            reactions 30-90, firing 40-95, throwing 40-90, strength 20-70,
            melee 20-100, psi 0-100.
            An ordinary trooper sits near the middle of each range. Reserve the
            top of a range for the one or two characters the range exists for.

armor       STR_ and capitals. If you do not know which, write
            STR_JOE_FATIGUES for a Joe and STR_COBRA_UNIFORM for Cobra.

weapons     A list in square brackets of STR_ ids, most characteristic first.
            Two or three. These are what the character carries by default.

summary     One sentence, under 20 words. Used in lists and tooltips.

article     Three to six sentences for the in-game file index.


WRITE IT YOURSELF
-----------------
The file card text on the original toy packaging is somebody's copyright. Do not
transcribe it, do not lightly reword it, and do not quote from it. Work from
what the character IS - specialty, temperament, how they fight - and write the
summary and the article in your own words.

Same for the stats: they are a judgement about how the character plays, not a
figure to be looked up.


DO NOT INCLUDE
--------------
    - Any logo, trademark or trade dress, in text or as art.
    - Any image. This file is text only; artwork is handled separately.
    - Markdown. No headings, no bold, no bullet characters. Plain YAML only.
    - Commentary, preamble or a summary of what you did. The file and nothing
      but the file.


CHECK BEFORE SENDING
--------------------
    1. Does every block have all the keys, in the order above?
    2. Is every id unique, capitals, and prefixed STR_?
    3. Are all ten stats present as whole numbers inside their ranges?
    4. Is side exactly joe, cobra or neutral, lower case?
    5. Is the whole thing valid YAML - two-space indents, no tabs anywhere?
    6. Is every word of summary and article your own?

If you are sending more than about thirty characters, split them across several
files named characters_1.yml, characters_2.yml and so on, each complete and
valid on its own.
